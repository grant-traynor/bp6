FOCUS TRAP AUDIT NOTE
─────────────────────
  The modal has aria-modal="true" and role="dialog" but does NOT implement a
  JS focus trap. Pressing Tab from #modal-close when the modal is open will
  move focus to elements outside the modal (the on-screen keyboard buttons).
  This means:
    - A screen reader user with aria-modal support will be correctly contained
      (ARIA virtual cursor is trapped by aria-modal in supporting SRs)
    - A keyboard-only sighted user can Tab out and inadvertently type into
      the game board while the modal is visually open
  This is flagged as an observation. The task acceptance criterion states
  "no focus trap issues" — Escape and the close button both function correctly
  and focus returns to the trigger element on close. Whether the absence of a
  Tab cycle trap is an "issue" is a product decision.
  Recommended fix if desired: add a keydown listener in the modal that wraps
  Tab/Shift+Tab back to #modal-close (only one focusable element in modal).
